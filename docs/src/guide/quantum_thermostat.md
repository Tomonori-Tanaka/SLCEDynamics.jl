# The semi-quantum thermostat

```@meta
CurrentModule = SLCEDynamics
```

At low temperature a *classical* thermostat is qualitatively wrong: equipartition
puts ``k_BT`` into every magnon mode, so the specific heat stays finite as
``T \to 0`` and high-frequency modes are vastly over-occupied.
[`QuantumThermostat`](@ref) implements the semi-quantum colored-noise thermostat of
Barker & Bauer, PRB **100**, 140401(R) (2019): the thermal-field power spectral
density is the classical one times the quantum fluctuation–dissipation factor

```math
\theta(x) = \frac{x}{e^{x} - 1}, \qquad x = \frac{\hbar|\omega|}{k_B T},
```

**without** the zero-point term. Magnon-mode occupations then follow Bose–Einstein
statistics (the specific heat goes to 0 as ``T \to 0``) instead of classical
equipartition. No zero-point term means ``T \to 0`` hands back the deterministic
package — the ecosystem's ground-state anchors survive.

## Usage

```julia
res = run_llg(prob, config0; dt = 1.0, nsteps = 100_000,
              kT = 0.005, seed = 1,
              thermostat = QuantumThermostat(),
              observables = standard_observables(H))
res.thermostat        # "quantum"
```

The colored noise is generated by a cascade of biquad filter sections applied to
the **same** per-step white Philox draws the classical thermostat uses — zero extra
draws, and a same-seed classical and quantum run share one underlying white
realization. At step 0 the filter state is initialized in its exact stationary law
(also Philox-keyed), so a run is a pure function of the seed with no burn-in and no
carried state before step 1.

The runtime cost is negligible: zero extra draws per step, and the biquad cascade
is arithmetic-light next to the SCE gradient. On the A100 GPU path the measured
quantum-vs-classical step-time overhead at the l044 production sizes was within
timing noise at 4³ and **+0.4%** at 8³ (see [GPU](gpu.md) and the decision record
`docs/specs/quantum-thermostat.md` Q4) — pick the thermostat on physics, not cost.

A small run, live (8 sites, `kT·dt/ħ ≈ 0.008`):

```@example qt
using SLCEDynamics, SLCEMonteCarlo, SLCE
import Spglib
using LinearAlgebra, Random

lat = Lattice(Matrix(1.0 * I(3)))
cell = Crystal(lat, reshape([0.0, 0.0, 0.0], 3, 1), [1], ["Fe"])
basis = SLCEBasis(cell, BasisSpec(; nbody = 2, cutoff = 1.1, lmax = [1],
                                 soc = false);
                 backend = SpglibBackend(), images = AllImages())
model = SLCEModel(basis, 0.0, [-0.01])
H = TiledHamiltonian(model; dims = (2, 2, 2))
prob = LLGProblem(H; magmom = 2.2, alpha = 0.05)      # α ≲ 0.05: see the caveats
config0 = SLCEMonteCarlo.from_matrix(repeat([0.0, 0.0, 1.0], 1, n_sites(H)))

res = run_llg(prob, config0; dt = 1.0, nsteps = 2000, kT = 0.005, seed = 3,
              thermostat = QuantumThermostat(),
              observables = standard_observables(H))
stats = equilibrium_stats(res; evaluables = Evaluable[])   # raw time averages only
(thermostat = res.thermostat, energy = stats[:energy].mean[1],
 err = stats[:energy].err[1])
```

## Validity window and guards

- **Hard bound**: `run_llg` throws an `ArgumentError` unless
  ``\tau = k_BT\,\Delta t/\hbar \in [10^{-4}, 0.1]``. Above 0.1 the discrete
  Nyquist band no longer comfortably contains the support of ``\theta`` — shrink
  `dt` for hot runs (the error message names the compliant `dt`;
  ``dt \le 0.05\,\hbar/k_BT`` is recommended for ≤ 1% spectral warp at occupied
  modes). Below ``10^{-4}`` the filter-coefficient conditioning degrades — and at
  such ``\tau`` every physical mode is frozen anyway (``\hbar\omega \gg k_BT``).
- **Markovian damping**: the damping stays local/Markovian (the QTB
  approximation), so detailed balance is broken; mode occupations are accurate to
  ~1% only for ``\alpha\,(\hbar\omega/k_BT) \lesssim 0.03`` — keep
  ``\alpha \lesssim 0.05`` for quantum-statistics observables. The classical
  α-independence gate does **not** generalize to quantum runs.

## Statistics on quantum runs

The equilibrium of a `QuantumThermostat` run is **not** a Boltzmann ensemble.
Fluctuation-formula evaluables (specific heat ``\mathrm{var}(E)/k_BT^2``,
susceptibility, Binder — including the `standard_evaluables()` default) estimate
something else there, so [`equilibrium_stats`](@ref) **throws** on a quantum run
with nonempty `evaluables` unless you insist with `allow_evaluables = true`. Pass
`evaluables = Evaluable[]` for the raw time-average stats (always valid), and take
response functions from finite differences across runs (e.g. specific heat from
``d\langle E\rangle/dT``).

``S(q,\omega)`` machinery is trajectory-level and stays valid on quantum runs; the
intensities are then **semi-quantum**. The detailed-balance asymmetry is not
reproduced, and a classical→quantum intensity correction factor must **never** be
stacked on top of quantum-thermostat data. The `SLCEMonteCarlo` Metropolis
cross-checks apply only to [`ClassicalThermostat`](@ref) — a deliberate
MC-mismatch tripwire is part of the gate set.

## Compatibility and persistence

- **Classical mode is untouched**: `ClassicalThermostat()` (the default) is the
  existing white-noise path, byte-identical to previous package versions for the
  same seed.
- **The shipped filter** matches ``\theta`` to 0.41% relative over the occupied
  band (measured certificate: max relative error 4.11e-3 on ``x \in [0.01, 6.6]``,
  max absolute error 7.17e-5 on ``(6.6, 200]``, ``H(0) = 1`` exact; full record in
  `docs/specs/quantum-thermostat.md`). Its coefficients are trajectory-defining
  package constants with a provenance tag (`_QT_FILTER_ID`).
- **Checkpoints are refit-proof**: schema v3 stores the discrete filter
  coefficients and the filter state; [`resume`](@ref) rebuilds the recurrence from
  the **stored** coefficients verbatim — never from the current package constants —
  so a future filter re-fit cannot change a resumed trajectory or brick old files.
  See [checkpointing](checkpointing.md).
- The GPU driver takes the same `thermostat` keyword with the same validation; see
  [GPU](gpu.md).

## A worked example

`examples/bloch_mt.jl` (in the repository) runs a small cubic ferromagnet under
both thermostats across temperatures and prints ``M(T)`` against linear
spin-wave estimates: the classical magnetization deficit is linear in ``k_BT``,
while the quantum thermostat freezes out the high-``\omega`` magnons at low
``T`` — the discrete-grid signature of the Bloch ``T^{3/2}`` law. The
``S(q,\omega)`` counterpart (per-mode intensities across a dispersion, gated
against the linear-response prediction) is the "G6" testset in
`test/unit/test_quantum_thermostat.jl`.
